# axum-native example

Demonstrates the `#[orpc]` workflow on plain Axum handlers.

No `router!` macro. No `os()` builder. Just annotate your existing Axum handlers
and get an auto-built router plus a generated TypeScript contract.

## The API

```rust
use axum::{extract::State, Json};
use orpc::orpc;

// 1. Annotate your plain Axum handlers
#[orpc(method = "POST", path = "/planet/list")]
pub async fn list_planets(State(db): State<Db>) -> Json<Vec<Planet>> {
    Json(db.list())
}

#[orpc(method = "GET", path = "/ping")]
pub async fn ping() -> Json<String> {
    Json("pong".to_string())
}

#[tokio::main]
async fn main() {
    // 2. Auto-built Axum router — no manual .route() calls
    let app = orpc::router(Db::new());

    // 3. Generate TypeScript contract
    orpc::generate_contract()
        .output("client/src/rpc/index.ts")
        .unwrap();

    let listener = tokio::net::TcpListener::bind("0.0.0.0:3002").await.unwrap();
    axum::serve(listener, app).await.unwrap();
}
```

## Generated TypeScript

Running the server generates `client/src/rpc/index.ts`:

```typescript
// AUTO-GENERATED by orpc — do not edit manually.

import { z } from "zod";
import { oc } from "@orpc/contract";
import { openapi } from "@orpc/openapi";

export const PlanetSchema = z.object({ ... });

export const contract = {
  ping: oc
    .meta(openapi({ method: "GET", path: "/ping" }))
    .output(z.string()),

  planet: {
    listPlanets: oc
      .meta(openapi({ method: "POST", path: "/planet/list" }))
      .output(z.array(PlanetSchema)),
  },
} as const;

export type Contract = typeof contract;
```

## How it works

| Feature | Mechanism |
|---------|-----------|
| Handler discovery | `inventory::submit!` at link time — no central list |
| Auto-router | `orpc::router(state)` iterates discovered `HandlerRegistration` entries |
| TypeScript contract | `orpc::generate_contract()` iterates discovered `HandlerMetadata` entries |
| State type erasure | Macro extracts `State<S>` from handler signature, emits concrete `downcast_ref::<S>()` |
| Zero user boilerplate | Just `#[orpc(method, path)]` — handler unchanged |

## Structure

```
examples/axum-native/
├── src/
│   ├── main.rs              — server entry, orpc::router() + generate_contract()
│   ├── models.rs            — Planet, FindPlanetInput, CreatePlanetInput, Db
│   └── handlers/
│       ├── mod.rs
│       ├── ping.rs          — #[orpc(method = "GET",  path = "/ping")]
│       └── planet.rs        — #[orpc(method = "POST", path = "/planet/...")]
└── client/src/rpc/
    └── index.ts             — auto-generated TypeScript contract
```

## Compared to manual Axum

```rust
// Before — manual registration
let app = Router::new()
    .route("/ping",          get(ping))
    .route("/planet/list",   post(list_planets))
    .route("/planet/find",   post(find_planet))
    .route("/planet/create", post(create_planet))
    .with_state(db);

// After — auto-discovered
let app = orpc::router(db);
```

## Next steps

- **Zod schemas**: Add `#[derive(ZodTs)]` to `Planet`, `FindPlanetInput` etc.
  once `zod_rs_ts` is wired in — the TypeScript output will include full
  Zod schema validation instead of `z.unknown()` placeholders.
- **`cargo orpc watch`**: CLI tool (Phase 4) will auto-regenerate
  `client/src/rpc/index.ts` on every Rust file change.
- **Error inference**: `#[derive(OrpcErrors)]` on `AppError` enum will
  auto-populate `.errors({...})` in the generated contract (Phase 3).
